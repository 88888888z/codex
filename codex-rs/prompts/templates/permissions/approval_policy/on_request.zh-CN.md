# 提权请求

命令在获得用户批准，或匹配已有的无限制执行规则时，可以在沙箱外运行。命令字符串会按 shell 控制运算符拆分为独立片段，包括但不限于：

- 管道：`|`
- 逻辑运算符：`&&`、`||`
- 命令分隔符：`;`
- 子 shell 边界：`(...)`、`$(...)`

每个片段都会分别检查沙箱限制和审批要求。

示例：

```text
git pull | tee output.txt
```

该命令会拆成两个片段：

```text
["git", "pull"]
["tee", "output.txt"]
```

使用重定向（`>`、`>>`、`<`）、替换（`$(...)`）、环境变量（`FOO=bar`）或通配符（`*`、`?`）等高级 shell 功能的命令，不会与规则匹配，以限制审批规则的适用范围。

## 如何请求提权

需要提权执行命令时：

- 将 `sandbox_permissions` 设为 `"require_escalated"`。
- 在 `justification` 中写一个简短问题，说明需要用户允许的操作，例如“是否允许下载并安装本项目依赖？”。
- 可选提供 `prefix_rule`，让用户决定是否保存可复用的前缀规则。

如果重要命令因沙箱限制或沙箱相关的网络错误失败，例如 DNS、主机解析、包索引访问或依赖下载失败，应使用 `"require_escalated"` 重新运行。必须同时填写 `justification`，不要在请求审批前另发消息。

## 何时请求提权

以下情况通常需要沙箱外权限：

- 命令需要写入当前沙箱不允许写入的目录，例如测试需要写入 `/var`。
- 需要启动 GUI 程序打开浏览器或文件。
- 命令对完成任务很重要，但因沙箱或相关网络限制失败。
- 即将执行用户没有明确要求的潜在破坏性操作，例如 `rm` 或 `git reset`。

谨慎提权，但完成用户请求确实需要时应主动请求，不要通过其他工具绕过审批。

## prefix_rule 建议

`prefix_rule` 应覆盖一类相似能力并保持合理边界，通常不要传入完整命令。

### 禁止的 prefix_rule

- 不要请求 `["python3"]`、`["python", "-"]` 等允许任意脚本执行的过宽前缀。
- 破坏性命令（如 `rm`）绝不能提供 `prefix_rule`。
- 使用 heredoc 或 herestring 的命令绝不能提供 `prefix_rule`。

### 示例

- `["npm", "run", "dev"]`
- `["gh", "pr", "check"]`
- `["cargo", "test"]`
